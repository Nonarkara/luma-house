# MSH pass — the tools explain themselves, and the page stops moving

**Date:** 2026-10-22
**Law:** `docs/MSH-DESIGN-LAW.md`
**Scope:** the whole system at 390 × 844, 1024 × 768 and 1440 × 900 — the plan
view with the sample apartment, the code check in the inspector, the scale chip,
the tool dock and the bottom chrome.
**Gate:** `e2e/spatial.spec.ts` — 15 tests (13 desktop, 2 phone); 5 of them new.
**Result:** 5 findings fixed, 1 candidate examined and refuted, 1 deliberate
choice recorded.

---

## Found

### 1. The Window and Door tools said nothing at all — 1440, 1024, 390

`.draw-hint` was rendered only for `activeTool === 'draw'`. Choosing **Window**
or **Door** produced no instruction of any kind.

Measured, after clicking Window: `.draw-hint` count **0**. The tool's own
name was the only clue, and the only way to learn that a click on a wall
places an opening was to click and look at what happened.

The tool's icon was `PanelLeftClose` — a collapsed-panel glyph in a tool that
places a window.

*Task cost:* the whole "add a window" task became a guess. A drawing can have
doors and windows that nobody can put in.

### 2. A status message moved the drawing — 1440 (114 px), 1024 (396 px)

`.toast` was `position: static` at the app-shell level, so it became a third
row of a `48px minmax(0, 1fr)` grid.

| | app-shell rows | the drawing |
| --- | --- | --- |
| 1440 × 900 | `48px 811px 41px` | 1246 × 890 → 1406 × 1004, x 41 → −39 |
| 1024 × 768 | `48px 679px 41px` | 673 × 481 → 1228 × 877, x 240 → −38 |

The drawing lost 41 px of height, re-fitted, and slid out of the frame; when
the message expired it snapped back. Every click that produced a message moved
the work under the hand.

### 3. The instruction line came and went with the tool — 1440, 1024, 390

The hint was a row of the canvas frame that only existed for the pencil.
Choosing another tool removed the row, the frame changed height and the
drawing re-fitted — the same movement as finding 2, from a different cause.

### 4. The code check was a 202 px ribbon of mono — 1440 (21 chars/line), 1024 (17)

`.code-issue-row` was `grid-template-columns: 80px 1fr` inside a 344 px
inspector, so the finding body got **202 px**. And `.inspector-content p`
(0,1,1) beat `.code-issue-body` (0,1,0), so the body rendered at 16 px
**JetBrains Mono** instead of the 11 px it asked for.

A sentence, set in mono, 21 characters a line, with a **12 px title over a
16 px body** — the hierarchy inverted. Each finding was 189 px tall; the
panel was 5665 px.

### 5. The scale chip had 947 px of nothing in it — 1440

`.scale-chip .ruler-arm { margin-left: auto }` pushed **Calibrate** to the far
edge of a 1312 px chip. The site dimension ended at x = 224; the button
started at x = 1172. **947 px of void**, and a lone `·` separator stranded in
it — a separator with nothing on either side.

### Examined and refuted: the room key

`.plan-room-key` measured 240 × 651 with 264 px of content. The 387 px below
the last room is **the frame's** empty column, not the key's: the key's own
border ends at its last entry, and the void belongs to the drawing. No
repair; the key is 240 px wide because the room names and areas are, it sits
outside the drawing viewport, and it is the reader's map from number to room.
Recorded as deliberate.

---

## Changed

1. **Every tool says what it does.** `TOOL_HINTS` in `src/App.tsx` gives each
   of the four tools its own sentence, and the Window tool's icon is
   `AppWindow` — a window, not a collapsed panel.
2. **The instruction line is a permanent row.** It is always on screen in the
   plan view and changes with the tool, so choosing a tool cannot move the
   drawing.
3. **The toast lives inside the drawing stage**, in the band below the
   drawing that already holds the sun card and the zoom control. It is no
   longer a row of the app-shell, and it never blocks a click
   (`pointer-events: none`).
4. **The code check reads.** The badge and its severity sit on one line, the
   finding gets the full measure, the body is set in Source Sans 3 and the
   title is bigger than the body.
5. **The scale group and its action stay together.** Calibrate sits beside
   the number it acts on, and the separator that stood alone in the void is
   gone.

## Verified

Measured on the built bundle, in a real browser, at 390 × 844, 1024 × 768 and
1440 × 900.

| | before | after |
| --- | --- | --- |
| the Window tool's instruction | none | "Click a wall to place a window" |
| the app-shell's rows while a message is up | 3 | 2 |
| the drawing during a message | moved 114 px (1440) / 396 px (1024) | **byte-identical** to before |
| the drawing when the tool changes | re-fitted | **byte-identical** to before |
| the finding's measure | 202 px, 21 chars/line, mono | 294 px, 55 chars/line, Source Sans 3 |
| one finding's height | 189 px | 125 px |
| the code-check panel | 5665 px | 4444 px |
| the gap between the site size and Calibrate | 947 px | 12 px |

The message test compares the canvas, the drawing viewport, the instruction
line, the scale chip and the frame — every box it can name — before, during
and after the message, at all three viewports, and requires them to be equal.
On the phone it also requires the message not to touch the tool dock.

**Gates, each mutation-checked.** A gate that cannot fail is worse than no
gate, so every repair was broken on purpose and the gate had to notice:

| mutation | gate | result |
| --- | --- | --- |
| the toast back to a static strip in the app-shell | a status message never changes the layout | **killed** (rows became `48px 810px 42px`) |
| the instruction line shown for the pencil only | every tool says what it does | **killed** |
| the same, measured for movement | switching tools never moves the drawing | **killed** |
| the finding back to an 80 px badge column and mono | a finding is read, not squeezed into a ribbon | **killed** |
| Calibrate pushed to the far edge again | the scale group and its action stay together | **killed** |

**The first attempt at each mutation was a false negative** and was caught by
the harness: the suite runs the built bundle, so a mutation that is not
rebuilt never reaches the browser. Two mutations that "passed" were measured
against the old build and had to be redone.

## Remaining

- **The finding's own measure is still narrow** — 55 characters a line at
  1440 in a 344 px panel. It is now readable prose in the house's body face
  rather than a mono ribbon, but the panel is narrow and widening it would
  take drawing space from the plan.
- **The code check sits about 1000 px down the inspector**, under the scale
  and room calibration sections, which are ordered first on purpose. It
  earns its scroll — 13 real findings — but a reader looking for the code
  check has to pass two other cards to reach it.
- **The toast is a pill over the drawing on a phone**, in the band below it.
  It covers a corner of the sun card and the edge of the zoom control for
  2.6 seconds. Nothing is blocked — the message is `pointer-events: none` —
  and the phone gate requires it not to touch the tool dock.
- **The 1024 px layout is the tightest of the three**: the drawing viewport
  is 316 px tall there, and the code check is a 260 px measure.
